지저분한 코드를 깔끔하게 정리해드려요.

**할 일**: 개선할 수 있는 코드를 찾아서 더 좋게 만들어요.

## 사용법
- `/refactor` → 전체 스캔하고 개선점 제안
- `/refactor [파일명]` → 그 파일에 집중
- `/refactor [문제 설명]` → 특정 문제 해결

## 1단계: 문제 영역 찾기
이런 "코드 냄새"를 찾아요:

**높은 우선순위**
- 여러 곳에 복사-붙여넣기된 같은 코드
- 30줄 넘는 긴 함수
- if문 안에 if문 안에 if문... (3단계 이상)
- 너무 많은 일을 하는 함수

**중간 우선순위**
- 헷갈리는 변수 이름
- 매직 넘버 (`if (status === 3)` 같은 거)
- 절대 쓰이지 않는 죽은 코드
- 헷갈리는 코드 설명하는 주석 (코드를 고쳐야지!)

## 2단계: 개선 제안
찾은 문제마다:

```
## 위치
[파일:라인 또는 함수 이름]

## 현재 코드
[문제 코드]

## 개선된 코드
[더 깔끔한 버전]

## 왜 이게 더 나은가
[간단히 설명]
```

## 3단계: 리팩토링 팁
흔한 개선 방법:
- **함수 분리**: 큰 함수를 작은 것들로 쪼개기
- **이름 바꾸기**: 더 명확한 이름 붙이기
- **중복 제거**: 재사용 가능한 함수 만들기
- **조건문 단순화**: 빠른 반환, 가드 절 사용

## 가이드라인
- 한 번에 하나씩 변경
- 동작은 그대로, 구조만 개선
- 임팩트 큰 것부터 시작
- 단순하게! 과도한 설계 금지!

💡 `/refactor` 실행하면 코드에서 제일 지저분한 부분을 찾아요.
